1. What Mira is, in one paragraph

Mira is a multi-agent workflow built in n8n. A project manager asks a question in plain English (for example, "Which tasks are blocked or at risk?"). An Orchestrator agent works out what kind of request it is and routes it to one of five specialist agents: Planner, Risk Assessor, Status Reporter, Milestone Tracker and Stakeholder Update. Vague requests go to a rule-based Clarifier, which asks for detail instead of guessing. All counting and date maths happen in code, so the AI only explains numbers it was given. A Grounding Check then verifies every task ID, risk ID, date, count, health rating and task status in the answer against the project files. Every request is traced in Langfuse with cost, tokens, latency and quality scores.

6. How to run it yourself (optional, about 10 minutes)

  1. In n8n (Cloud or self-hosted): Workflows → Import from file → workflow/mira_workflow.json.
  2. Add an OpenAI credential to the six agent nodes (Orchestrator, Planner, Risk Assessor, Status Reporter, Milestone Tracker, Stakeholder Update). No keys are stored in the file.
  3. Activate the workflow, open the Chat with Mira node and click Open chat. Try: "Which tasks are blocked or at risk?"
  4. Optional: run all 12 tests with python3 tests/run_tests.py --url https://<your-n8n>/webhook/mira (Python 3, no extra packages).
  5. Optional: connect Langfuse as described in the README, section "Setup", step 6.

Markdown files (.md) open in any text editor; they read best on GitHub, where they are formatted.
